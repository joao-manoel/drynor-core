# OSRS content transfer

Read the owning repository AGENTS.md and drynor-code-standards. Use drynor-content-development for asset/gameplay integration and drynor-kotlin-plugins for hooks. Resolve sibling repositories from the actual checkout. Source projects and reference caches are read-only inputs.

## Workflow

1. Identify what is actually OSRS: compare terrain/landscape archives and map-ID lists, not just region names. Record source revision, region/chunks/planes, XTEA policy and actual source gameplay handlers. A hybrid Gielenor region can already be byte-identical to native Drynor.
   For a large connected continent, derive its bounds from the cache and traversal links. Include subterranean regions, upper floors, interiors, instanced templates and the entrance/exit graph; screenshots and a named region list are only starting coordinates.
2. Inventory dependency closure before allocating IDs: floors, locations, object definitions, NPC/BAS, models, sequences/frames/bases, spots/projectiles, textures/materials/sprites, sounds, items and Java definition overrides. Explicitly record omissions and blockers.
3. Allocate IDs deterministically after inspecting physical destination archives/files and client limits. Import into a new packed output with the baseline preserved. Use strict source grammar and translate to native 727 representation; offsets alone do not convert formats. Refuse unknown payloads instead of silently skipping them.
4. Keep editable JSON/GLB/PNG or existing source representations and verify their binary round trip. Read every imported asset through native decoders and the actual client consumers. Compare all unaffected archive hashes, accounting for shared blobs such as materials.
5. Port source behavior through Drynor lifecycle, combat, pathfinding and persistence APIs. Preserve source mechanics and local gameplay customizations. Use Kotlin in org.drynor, compiled startup hooks and the dialogue DSL. Reference checkouts must not become runtime dependencies.
6. Keep diagnostic and normal encounter entry modes explicit: XP, drops, completion and persistence are separate gates. Diagnostic commands must not turn an existing session into a reward-bearing attempt.
7. Validate in stages: static map, instanced map, passive actors, animations/effects, collision/line of sight, combat, full encounter, logout/resume/death/exit and rewards. Distinguish automated checks from user-confirmed client tests. Build one Gradle project at a time when composite outputs are shared.
8. Promote only the validated cache with matching server/client artifacts. Keep portable runtime bindings, original cache and rollback artifacts outside Git. Disable diagnostic commands in production. Deployment and publishing require authorization from the current user task; the skill itself grants none.

For known Inferno pitfalls, conversion entry points and reusable evidence, read [references/inferno-lessons.md](references/inferno-lessons.md). Treat concrete IDs as historical evidence and recheck collisions for each import.

For animated imported scenery, native water/world-map conversion, equipment/pets and complete encounter rewards, read [references/zulrah-lessons.md](references/zulrah-lessons.md). These are observed pipeline constraints, not a mandate to copy source economic rates or historical IDs into a new feature.

Gielenor `Region.java` adds `Settings.OSRS_OBJECTS_OFFSET` to raw placement IDs only for its OSRS_MAP_IDS. The Zeah inventory found destination IDs already occupied with different definition bytes, so map placements and definitions must be remapped together. Never overwrite a Drynor object merely because the donor runtime ID matches.
The inventory's proposed object remaps are provisional per rectangle. Union all selected surface, cave and instance IDs and run one global allocation before import; separate regional plans can assign the same replacement ID to different assets.
Use read-only `osrs plan-zeah-object-ids <target-cache> <new-plan.json> <region-report.json> [more-reports...]` to union matching inventories. It verifies the donor Settings hash and source object payload hashes before allocating. `scopeComplete=false` means the output is evidence for further planning, not a production ID manifest.
The planner also follows object morph references recursively; a plan based only on directly placed definitions is incomplete. Run `osrs audit-zeah-object-deps <source-cache> <object-id-plan.json> <new-audit.json> [target-cache]` to strictly parse the closure and check source model/sequence/frame/base presence, plus whether missing donor frames exist in the target cache. This donor has frames that use the native 727 grammar; do not assume every referenced frame uses the OSRS transform grammar merely because its object came from an OSRS region. Distinguish a missing source frame file from a decoder failure. An ID-matched target frame would still need semantic comparison before reuse. Presence and decoding do not prove native conversion or client rendering.
For static NPC spawns, run `osrs inventory-zeah-npc-spawns <gielenor-root> <object-id-plan.json> <new-report.json>`. It reads the two files used by Gielenor's `NPCSpawns.init()`, filters by the selected region IDs and reports the donor's NPC-ID guard separately from parseable lines. An ID in the donor's skipped 15941..20000 band is not a live spawn. Identical NPC definition bytes can be reused only after checking dependent models, BAS and behavior; differing native-range definitions may be Drynor customizations and must not be overwritten.
Run `osrs audit-zeah-npc-deps <gielenor-cache> <npc-spawn-report.json> <new-report.json> [target-cache]` for OSRS-offset NPC definitions, their morphs and model/sequence/frame/base presence, plus a target check for missing donor frames. Its frame failures retain sequence IDs and sequence-to-NPC ownership. The command intentionally leaves native-range NPCs and combat-script dependencies for separate review. A donor with all NPC definitions present can still have absent animation frames; keep those NPCs blocked until the visual chain is resolved and checked in the client.
Run `osrs audit-zeah-terrain <gielenor-cache> <object-id-plan.json> <new-report.json>` before staging a large map set. It decodes every selected donor terrain, applies the established explicit-height normalization and verifies native tile encode/decode round trips. A byte-identical floor definition at the same file ID in both caches is only physical cache evidence; it does not establish that the OSRS terrain's overlay/underlay IDs have the same *visual meaning* in the 727 client. Calibrate floor ID translation against shared regions and the real client before packing maps.

The Gielenor client adds `OSRS_FLOOR_OFFSET=1000` to nonzero OSRS terrain floor IDs in `Class240`. `Class375` resolves special overlays after the offset (1005→file 111, 1051→97, 1084→113), retains selected IDs above 1000, and otherwise returns to the raw file index. `Class451` similarly retains underlay 1026 and otherwise returns to the raw index. The audit now reports these *effective* source files separately and searches byte-identical target aliases within the terrain byte range. The source overlay decoder also adds `OSRS_TEXTURE_OFFSET=2651` to OSRS textures, so identical floor payload bytes alone do not prove identical rendering. Never truncate a floor file ID above 254 into a terrain byte or overwrite an occupied Drynor definition. Audit free low IDs and texture semantics first; if capacity is insufficient, design a region-aware client/cache path and validate it on an isolated packed cache.
For this donor, texture remapping is applied only to overlay opcode 3, then `TextureLoader.replaceTexture` resolves material 7→42, 10→8, 59→2710 and otherwise returns the raw material. Opcode 2 retains its byte texture ID. Use the traced floor decoder to identify the actual opcode: `opcodeOrder` can be null for canonical payloads. The Zeah audit now records source and effective material IDs and their presence in both caches; material-file presence alone does not verify texture metadata, sprites or rendering.
The isolated `osrs preview-zeah-floor <gielenor-cache> <drynor-cache> <terrain-audit.json> <new-output-root>` command proves one CoX room (region 7951) with four new low floor files, one byte-identical alias and normalized terrain. It copies the packed baseline under `build`, verifies readback and all preexisting map archives, and records that it contains no objects/NPCs/gameplay. Its hardcoded mapping is a capacity probe, not the global Zeah mapping. Never launch or publish this terrain-only cache as a complete world.
The Drynor client scene loader has a source-region overlay palette analogous to its underlay palette. It retains unsigned 0..255 terrain bytes in an internal `IntArray` so an imported region can resolve a raw tile ID to a definition above 255, including rotated instance chunks. The palette defaults to identity; install a complete, validated mapping before rebuilding an imported scene, and keep an immutable snapshot for asynchronous loads. The world-map `area` decoder is separate; a scene palette alone does not prove map-screen fidelity.
The client's `WorldMap` `area` decoder now resolves overlay and underlay bytes by the source map square `(x shl 8) or y` through a snapshot of the same scene palettes. Its internal floor arrays and extra-floor tile records retain IDs above 255, and unsigned native bytes remain unchanged when no palette is installed. Imported map-area underlay IDs outside the terrain palette's 0..174 range fail closed; native map squares retain their unsigned value. This is a consumer foundation only: the Zeah world-map archive and palette manifest still need conversion, client rendering checks and minimap validation.
For item sources, Gielenor loads `data/npc/packedDrops.d` and the existing `data/item/packedSpawns/*.is`; the unpacked spawn text is not authoritative while the packed directory exists. Run `osrs inventory-zeah-npc-drops <gielenor-root> <npc-spawn-report.json> <npc-deps-report.json> <new-report.json>` for raw packed drop records tied to selected NPCs. The runtime applies further drop exclusions and dynamic/special tables, so raw entries are candidates, not the final loot policy. Run `osrs audit-zeah-item-deps <gielenor-cache> <npc-drop-report.json> <new-report.json>` to follow OSRS item note, stack, lend and placeholder links plus model presence. Preserve Drynor's native item definitions and economic rates; do not import a source drop table as a production rule without gameplay review.
